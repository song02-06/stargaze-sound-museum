# 验收演示

> 老师要看的是：**用户端、管理端、两个用户之间有可见互动；同一件投稿能新增、查看、编辑、删除；
> 数据能持久保存。** 下面这一场连续演示把这几件事一次性证明完。
>
> 前提：后端和前端都在跑（见 [`部署说明.md`](./部署说明.md) 或根 README「快速开始」），
> `ADMIN_TOKEN` 已配置，演示音频已生成。

## 一、三个会话，不要用一个浏览器伪装

| 会话 | 谁 | 怎么准备 |
| --- | --- | --- |
| **A** | 作者 | 正常浏览器窗口（保留 localStorage） |
| **B** | 听众 | 另一个浏览器 / 隐私窗口 / 另一台设备 |
| **C** | 管理员 | 同一个域名下的 `/admin` |

> 同一浏览器的普通标签页**共享 localStorage**，通常不是两个用户。
> 不要靠反复改昵称伪装成两个人 —— 会话 id 才是身份。
> 游客身份只跟随当前浏览器；注册后可在其他设备登录同一账号。作者 A、听众 B 请分别注册不同账号，投稿与回音需要登录。

## 二、一次连续演示

| # | 谁 | 操作 | 应该看到 | 数据库变化 |
| --- | --- | --- | --- | --- |
| 1 | A | `/bury` 录音/选文件 → 填标题、故事、地点、日期 → 分类选**演唱** → 勾原创声明 → 提交 | 牌上写「转人工复审了」；**不自动跳走** | `exhibit` INSERT（status=REVIEW, sound_type=SINGING, original_confirmed=TRUE）、`audit_record` INSERT（RULE）、`audit_record` INSERT（ASR） |
| 2 | C | 打开 `/admin`（**不刷新整页**，等 5 秒） | 队列自己多出一条，带**音频播放器**、地点、日期、演唱标签 | 无（只读） |
| 3 | C | 播放原声 → 通过 | 该项从队列消失，流水多一条 MANUAL | `exhibit.status` UPDATE、`audit_record` INSERT、`notification` INSERT |
| 4 | A | 看「我的声音」（不刷新整页） | 顶栏出现未读数字；消息里是该投稿的结果；`Nº` 可点，进公开详情 | 无（只读） |
| 5 | A | 点一条消息 | 未读数字减一，跳进展品页 | `notification.read_at` UPDATE |
| 6 | B | 打开该展品 → `/exhibit/编号/echo` → 写一句文字回音 → 发送 | 页面显示「**已经公开了**」，并立即出现在回音列表里 | `echo` INSERT（PASS）、`notification` INSERT |
| 7 | A | 回到「我的声音」 | 5–8 秒内出现新消息 + **回音收件箱**里能看到这条，能播放 | 无（只读） |
| 8 | B | 再录一条 10–30 秒语音回音发送 | 显示「**在等人工看一眼**」（默认 mock 识别） | `echo` INSERT（REVIEW）、音频文件落盘、`audit_record` INSERT（ASR=REVIEW） |
| 9 | C | 队列里出现这条语音；**没有转写文本也能直接播** | 听完写原因通过 | `echo.status` UPDATE、`audit_record` INSERT、两条 `notification` INSERT（发送人 + 展品作者） |
| 10 | A | 「我的声音」→ 该投稿 → **改一改** → 改标题和故事 → 送审 | 结果写在新牌上；编号仍然是原来那个 | 同一 `exhibit` 行 UPDATE（含 `updated_at`），**记录数不变** |
| 11 | A | 再改一次，故事里塞一个拦截词（例如「加微信」） | 显示「没通过」+ 原因；公开馆藏里搜不到了 | 同一行 UPDATE（status=REJECT） |
| 12 | A | 改回去，送审 | 重新通过，公开详情可访问 | 同一行 UPDATE（status=PASS） |
| 13 | B | 再给这件展品发一条文字回音 + 一条语音回音 | —— | `echo` INSERT ×2 |
| 14 | A | 「我的声音」→ 删除该投稿（先看清提示里的回音条数） | 馆藏和我的声音里都消失 | `exhibit` DELETE、`echo` DELETE；**音频文件全部消失**；`audit_record` 保留 |
| 15 | C | 流水页 | 仍能看到这件展品的全部历史流水 | 无（审核流水不删） |
| 16 | A/B | 手机用**移动网络**访问同一个 HTTPS 地址 | 授权麦克风后能录音、能上传、能看到同一批数据 | 同一后端、同一份库 |
| 17 | 运维 | `sudo systemctl restart starmuseum` | 再打开另一件没删的投稿：数据与音频都在 | 证明持久化路径正确 |

### 证明「多端互动」的两条最短路径

- **A → C → A**：投稿进管理端队列（不用刷新整页）→ 管理端通过 → 作者端收到结果与未读提示。
- **B → A**：B 发回音 → A 在 5–8 秒内看到未读消息 → 点进去落到具体展品。

## 三、证明数据库真的变了

不要只给一张「提交成功」的截图。三组查询，改前改后各跑一次：

```sql
SELECT id, no, title, keeper_id, status, sound_type, updated_at
FROM exhibit ORDER BY id DESC;

SELECT id, exhibit_id, author_id, kind, status FROM echo ORDER BY id DESC;

SELECT id, recipient_session_id, kind, target_no, read_at FROM notification ORDER BY id DESC;

SELECT id, target_type, target_id, stage, verdict, detail
FROM audit_record ORDER BY id DESC;
```

预期能指认出的三件事：

1. **编辑**：同一 `exhibit.id` / `no` 的 `title`、`full_text` 变了，行数**没变**；
2. **通知**：`notification` 只在「真的公开」之后出现（待审、被驳回的回音不产生 `ECHO_RECEIVED`）；
3. **删除**：`exhibit` 与 `echo` 行消失，`audit_record` 还在，`data/audio/` 下相关 WAV 消失。

连接方式见 [`数据库说明.md`](./数据库说明.md) 第四节。

## 四、可以被追问的点，与如实回答

| 追问 | 怎么答 |
| --- | --- |
| 审核是真的 AI 吗？ | **不是。** 只有本地规则词表 + 人工复审。之前那行「mock 判定：safe」已经删掉了 —— 那不是审核结果 |
| 语音回音怎么审核？ | 配了真实 ASR 就用转写文本走规则；**没配就一定转人工**。Mock 不生成任何转写内容，也不放行 |
| 演唱分类是怎么判断的？ | 不自动判断。由投稿人**自己选**，选了 `SINGING` 后端就强制转人工 |
| 原创声明有用吗？ | 后端必填：缺失或 `false` 直接拒收，并存进 `original_confirmed` |
| 展签能保证内容真实吗？ | 不能。它只保证展签是全文的**字符子序列**（限制删改），不等于语义真实性证明 |
| 收藏功能呢？ | 没有独立收藏。「你回应过的展品」是「我回应过什么」，不是收藏表，不要混着说 |
| 换设备还能是我吗？ | 可以注册账号，再在另一设备登录；纯游客身份不跨设备恢复 |
| 数据是怎么持久化的？ | H2 文件库 + 音频目录都在 `/srv/starmuseum/data` 绝对路径下，重启后仍在（步骤 17 现场证明） |

## 五、演示失败时先查什么

| 现象 | 先查 |
| --- | --- |
| 页面有卡片但播放 404 | `data/audio/` 里没有实际 WAV（只复制了 manifest） |
| `/admin` 一直提示进不去 | `ADMIN_TOKEN` 没配或服务没重启 |
| 录音按钮点了没反应 | 不是 HTTPS / 没给麦克风权限 |
| 队列不自动更新 | 标签页在后台被节流；切回来会补一次 |
| 刷新 `/mine` 404 | Caddy 少了 `try_files {path} /index.html` |
| `/api/ping` 返回 HTML | `/api/*` 被 SPA 的 `try_files` 接管了，检查 `handle` 顺序 |
