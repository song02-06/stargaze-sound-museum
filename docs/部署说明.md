# 部署说明

> 目标：**一个能被其他网络访问的 HTTPS 地址**，用户端和管理端连同一个后端，数据和音频持久化。
>
> ⚠️ 这份文档是**可重现的实施步骤**，不是「已经部署成功」的证明。
> 服务器、域名、密钥属于需要人提供的输入；没有这些，只能完成部署材料。

## 一、结构

单台 Linux 服务器，四层，没有多余组件：

```
电脑浏览器 / 手机浏览器 / 管理员浏览器
                  |
         https://你的实际域名
                  |
                Caddy                 ← 自动 HTTPS、前端静态文件、反向代理
         /        |        \
    前端 dist   /api/*    /audio/*
                  |         |
            Spring Boot :8081       ← systemd 常驻（只监听 127.0.0.1）
                  |
          H2 文件库 + 音频目录       ← 固定在 /srv/starmuseum/data
```

- **只跑一个后端进程**。不要让两份进程同时操作同一份 H2 文件。
- 前端 dist 由 Caddy 直接提供；**Vite 的 dev/preview 代理不会跟着 dist 一起变成生产代理**，
  生产站点必须配置真实反向代理。
- 课程没有指定 MySQL，本轮不换库。若课程另有要求，再单独调整。

## 二、准备（一次性）

### 1. 系统与服务用户

```bash
sudo useradd --system --create-home --home-dir /srv/starmuseum --shell /usr/sbin/nologin starmuseum
sudo mkdir -p /srv/starmuseum/{app,web,data/audio} /etc/starmuseum
sudo chown -R starmuseum:starmuseum /srv/starmuseum
sudo chmod 750 /srv/starmuseum
```

### 2. Java 与 Caddy

```bash
sudo apt install -y openjdk-17-jdk
# Caddy：按官方源安装（会自动带 systemd unit）
```

### 3. 环境变量文件（放真实密钥）

```bash
sudo cp deploy/starmuseum.env.example /etc/starmuseum/starmuseum.env
sudo nano /etc/starmuseum/starmuseum.env       # 改成真实值
sudo chown starmuseum:starmuseum /etc/starmuseum/starmuseum.env
sudo chmod 600 /etc/starmuseum/starmuseum.env
```

必改项：

| 变量 | 说明 |
| --- | --- |
| `ADMIN_TOKEN` | **必须设**，否则管理后台关闭。用 `openssl rand -base64 24` 生成 |
| `SPRING_DATASOURCE_URL` | 用**绝对路径**：`jdbc:h2:file:/srv/starmuseum/data/museum` |
| `MUSEUM_AUDIO_ROOT` | 用**绝对路径**：`/srv/starmuseum/data/audio` |
| `ASR_PROVIDER` | 没有真实密钥就保持 `mock`（语音回音全部转人工） |

> **`ASR_PROVIDER=baidu` 只有在真实密钥 + 真人录音验证识别文本确实对应音频之后才采用。**
> 环境文件不提交 Git、不截图、不外发。

## 三、构建与上传

在开发机上：

```bash
# 1）演示音频（只需一次，但新库首次部署必须有实际音频文件）
cd code && node tools/gen-audio.mjs

# 2）后端：测试 + 打包
cd backend && mvn test && mvn -DskipTests package
#  产物：target/starmuseum-2.0.0.jar

# 3）前端：构建
cd ../frontend && npm ci && npm run build
#  产物：dist/
```

上传：

```bash
scp code/backend/target/starmuseum-2.0.0.jar  user@server:/srv/starmuseum/app/
scp -r code/frontend/dist/*                   user@server:/srv/starmuseum/web/
```

- `app/` 与 `web/` 是**每次发版都可以整个替换**的目录；
- `data/`（库 + 音频）是**绝对不能替换**的目录。

### 首次部署要复制种子音频

```bash
# 新库第一次起之前：把演示音频放到音频根目录，否则页面有数据但播放 404
scp -r code/backend/data/audio user@server:/srv/starmuseum/data/
```

> 只有 `audio-manifest.json`（时长/波形）而没有实际 WAV，就是「有数据、播不出声」。
> 以后更新**不得覆盖** `data/audio/` 里用户上传的文件（文件名带 UUID，正常覆盖也不会撞，
> 但不要整目录 `rsync --delete`）。

## 四、跑起来

### 1. systemd

```bash
sudo cp deploy/starmuseum.service /etc/systemd/system/starmuseum.service
sudo systemctl daemon-reload
sudo systemctl enable --now starmuseum
sudo systemctl status starmuseum
sudo journalctl -u starmuseum -f          # 看日志
```

启动成功时日志里会有种子写入或「库里已有数据，跳过种子写入」。

### 2. Caddy

```bash
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile            # 把 museum.example.com 换成你的域名
sudo systemctl reload caddy
```

- 域名 DNS 要指向这台机器；**80 / 443 要放通**（Caddy 自动申请证书）。
- 前端是 `createWebHistory`：`try_files {path} /index.html` 必须有，
  否则刷新 `/mine`、`/exhibit/0249`、`/admin` 会 404。
- `/api/*` 与 `/audio/*` 走反向代理，**不能剥掉前缀**（后端注册的就是带 `/api` 的路径）。

### 3. 验证

```bash
curl -I  https://你的域名/                 # 200，Content-Type: text/html
curl     https://你的域名/api/ping          # {"code":0,...}
curl -I  https://你的域名/api/ping          # 200，Content-Type: application/json（不是 HTML！）
curl -I  https://你的域名/exhibit/0249      # 200（深层路由刷新不 404）
curl -I  https://你的域名/audio/exhibits/rain.wav   # 200，Accept-Ranges: bytes
```

最容易漏的两条：

- API 请求被回落成首页 HTML（说明 `try_files` 顺序写错，`/api` 也被 SPA 接管了）；
- 深层路由刷新 404（说明没配 `try_files`）。

## 五、上线后必须人工验证的清单

在**两种不同网络**（比如家里 Wi-Fi 与手机移动数据）各做一遍：

- [ ] 打开 `https://你的域名/`，馆藏能列出
- [ ] 深层路由直接刷新（`/mine`、`/exhibit/编号`、`/admin`）不出现 404
- [ ] `/admin` 输入 `ADMIN_TOKEN` 能进；输错进不去
- [ ] 手机浏览器**授权麦克风**后能现场录音、上传、播放（HTTPS 是前提）
- [ ] `/audio/...` 能播放、能拖动进度条
- [ ] 投稿进队列 → 管理端不刷新整页能看到 → 通过 → 作者端看到结果
- [ ] 另一个浏览器发回音 → 作者端 5–8 秒内出现未读消息
- [ ] 编辑同一件投稿：编号不变、内容更新
- [ ] 删除展品：相关音频文件一起消失
- [ ] `sudo systemctl restart starmuseum` 之后数据与音频都还在
- [ ] **重启整台服务器**之后再检查一遍

> 外网浏览器录音需要 HTTPS 安全上下文与麦克风授权。
> 只交一个 HTTP 公网 IP，结果是「能看不能录」。

## 六、更新发版

```bash
# 停服务 → 换 jar / dist → 起服务（data 目录不动）
sudo systemctl stop starmuseum
sudo cp starmuseum-2.0.0.jar /srv/starmuseum/app/
sudo rm -rf /srv/starmuseum/web/* && sudo cp -r dist/* /srv/starmuseum/web/
sudo chown -R starmuseum:starmuseum /srv/starmuseum/{app,web}
sudo systemctl start starmuseum
```

`index.html` 已配置 `no-cache`，`/assets/*` 长缓存 —— 发版后用户刷新即可拿到新入口。

## 七、备份与恢复

**数据库与音频必须一起备份、一起恢复。**

```bash
# 备份
sudo systemctl stop starmuseum
sudo tar czf /var/backups/starmuseum-$(date +%F).tar.gz -C /srv/starmuseum data
sudo systemctl start starmuseum

# 恢复
sudo systemctl stop starmuseum
sudo tar xzf /var/backups/starmuseum-2026-10-22.tar.gz -C /srv/starmuseum
sudo chown -R starmuseum:starmuseum /srv/starmuseum/data
sudo systemctl start starmuseum
```

只复制 `museum.mv.db` 而不复制 `audio/`，页面会有数据但播放 404 ——
库里存的是音频的**相对路径**。

## 八、静态托管为什么不够

GitHub Pages / Vercel 静态托管只能承载前端，**不能独立承载当前 Java 服务与 H2 写入**。
把首页放上网不等于整套项目部署完成。
