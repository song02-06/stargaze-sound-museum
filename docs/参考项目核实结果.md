## 一、先说结论

1. **没有可以整包套用的同类项目** —— 计划书第十章的判断是对的。以「声音博物馆 / 星空漂流瓶」为产品形态的开源项目，搜到的都是概念相近但形态不同的小仓库。
2. **计划书里两个「起点」选择都需要改** —— `itbaima-study/SpringBoot-Vue-Template-Jwt` 与 `Aizener/three-template` 都是**未声明许可证**的仓库，且后者已停更三年。整包 fork 进课程作业有实际风险。
3. **计划书里三个「关键参考」已经死了** —— `unconed/ThreeAudio.js`（2015 年后无提交）、`wayou/3D_Audio_Spectrum_VIsualizer`（2015）、`GraemeFulton/ThreeJS-3D-Music-Visualizer`（2016）。思路可以看，代码别抄。
4. **依赖类的选择全部核实无误** —— `houbb/sensitive-word`、`Baidu-AIP/java-sdk`、`staskobzar/vue-audio-visual` 都是许可证清晰、可放心当依赖用的。
5. 因此本次 Demo 的搭法：**官方脚手架起项目 + 有明确许可证的依赖 + 只借鉴思路不抄代码**。

## 五、最终建议组合

| 用途 | 选择 | 理由 |
| --- | --- | --- |
| 后端起点 | **Spring Initializr**（start.spring.io）自己生成 | 零许可证风险、版本永远最新，比 fork 任何模板都干净 |
| 前端起点 | **`npm create vite@latest`** + three | 同上；想要声明式写法再换 TresJS（MIT） |
| 星轨视觉 | three.js 官方 examples + `ZGdadong/Three.js-3D-Earth` 的着色器写法 | 官方 MIT，参考实现活跃 |
| 音频驱动 | 自己写 `AnalyserNode` → 参数映射（Demo 里已实现） | 计划书里那三个参考仓库全部停更十年以上 |
| 音频可视化组件（可选） | `staskobzar/vue-audio-visual`（MIT） / butterchurn（MIT） | 许可证干净、活跃 |
| 审核 | 自研 DFA（约 80 行，Demo 里已实现）→ 后期换 `houbb/sensitive-word` | 先零依赖跑通，再升级 |
| 语音识别 | 百度官方 **REST 接口**（Demo 里已实现） | 不需要引 SDK 依赖 |
| DeepSeek | 手写 `RestClient`（Demo 里已实现） | 一次 HTTP 调用，不值得为它引框架 |
| 模拟留言数据 | `rany2/edge-tts` | 仍是批量合成的最优解 |

**一句话**：这个项目里真正值得「拿来用」的是**依赖**（敏感词、波形组件、three.js），
而不是**模板**。模板带来的收益远小于它带来的许可证与维护风险。
