# 星轨 · 声音博物馆：业务逻辑升级方案

日期：2026-10-31  
依据：当前 Vue 前端、Spring Boot 服务与配置的静态阅读，以及本次聊天确认的导航行为。本文是实施建议，尚未修改业务代码，也未执行新的业务测试。

## 1. 升级目标

让用户自然完成三件事：遇见值得听的声音、留下有意义的回应、回来找回自己的声音与互动。

延续“声音博物馆”的气质：保留随机打捞、声音的时间地点和故事、公开回音与历史之声。近期不加入关注关系、私信、积分、签到、排行榜或复杂推荐，避免把作品变成常规内容社区。

优先顺序：先修身份和状态闭环，再补找回与互动，最后增强策展与发现。

## 2. 现状与需要保留的能力

| 业务 | 当前实现 | 升级判断 |
| --- | --- | --- |
| 身份 | 设备游客身份、账号注册、Cookie 登录、账号跨设备取回 | 已实现，不能再列成从零建设功能 |
| 导航 | 未登录显示“登录”，登录后显示“我的声音” | 保留；它控制入口展示，目前不等同于路由访问规则 |
| 投稿 | WAV、时间地点、故事、声音分类、原创声明，服务端读取时长和波形 | 保留；当前配置主声音 10–60 秒，语音回音 10–30 秒 |
| 审核 | 本地词表、语音转写辅助、人工复审；演唱强制人工 | 保留，不宣称已接入大模型内容审核 |
| 打捞 | 普通声音与历史声音、概率选择、近期记录去重 | 调整选择顺序和首次体验 |
| 我的声音 | 投稿管理、收到的公开回音、发出的回音、消息、回应过的展品 | 保留；“回应过”不是收藏 |
| 编辑与删除 | 原编号编辑并重审；删除连带清理回音、使消息目标失效，审核流水保留 | 保留已有一致性处理，补清状态和用户预期 |

当前已经正确的设计：公共馆藏只显示通过内容；语音回音无法可靠转写时转人工；未公开的回音不通知展品作者；删除音频在数据库事务提交后执行。升级不应拆掉这些规则。

## 3. 第一阶段：先修业务连续性

### 3.1 退出登录后的游客身份恢复

**实施复核更正：** Session.register 已经更换原 deviceKey，原游客密钥不能取回已注册账号。因此原先有关“注册后仍关联原 deviceKey，退出后反复 401”的推断不成立。这部分现有实现正确，保持不变；AuthFlowTest 已覆盖旧设备密钥无法取回账号的场景。

**目标规则：** 注册继承原游客数据；退出后获得独立游客身份；再次登录仍回到原账号。界面身份与服务端可用身份一致。

**最小实施：** 退出时保留账号与内容，更新浏览器游客 deviceKey 后创建新游客会话。服务端游客接口不应把已注册身份作为游客返回；会话过期也走同一游客恢复流程。已有浏览器中的旧 deviceKey 需要在恢复时直接换新，不引入一套通用迁移框架。

登录已有账号时不自动合并另一游客身份的数据，避免无意改变内容归属；注册当前游客才继承当前游客内容。这个区别应写在登录与注册说明中。

**落点：** frontend/src/api/index.js、store/museum.js；后端 SessionService、SessionController、AccountService。

**验收：** 游客打捞→注册→退出→继续打捞→重新登录，均不出现身份反复失效；同一浏览器退出后能注册另一个账号；原投稿仍归原账号。

### 3.2 明确游客和账号的操作边界

**现状：** 隐藏“我的声音”后，直接打开 /mine 仍可进入游客个人页，投稿与回音仍支持游客身份。这是当前实现，不是仅凭导航隐藏就完成了登录要求。

**建议采用的新规则：**

| 操作 | 游客 | 已登录账号 |
| --- | --- | --- |
| 星空、馆藏、历史之声、公开详情与试听 | 允许 | 允许 |
| 随机打捞 | 允许，记录仅跟随当前游客身份 | 允许，跟随账号 |
| 开始录音、选择文件和填写草稿 | 允许本地准备 | 允许 |
| 正式投稿、发送回音、收藏 | 提示登录后继续 | 允许 |
| 我的声音与投稿编辑 | 转到登录页 | 允许本人操作 |

这是产品调整建议，不是对旧游客规则的错误判定。实施时前端入口和后端写入规则一起改；旧游客内容不删除，注册仍可继承。

登录成功后返回原来的投稿或回音位置，恢复待提交内容，用户确认后再提交。只恢复站内目标。文本草稿可本地保存；录音与选中文件在登录切换过程中保留在应用内存中，刷新前明确提示尚未保存，近期不承诺刷新后恢复音频。

“登录 / 注册”仍在同一页面切换；顶栏未登录只写“登录”，成功后替换成“我的声音”。退出后回到星空，清空个人页面的旧账号数据。

### 3.3 打捞先排除近期内容，再决定内容类型

**现有问题：** DrawService 先选普通/历史类型，再在该类型内去重。当某类型近期已全部听过，另一类型仍有新内容时，仍可能重复抽到前者。类型加 ID 的现有区分是正确的，问题在选择顺序。

**目标规则：**

1. 从已公开的普通展品与历史声音组成可用池，保留类型区分。
2. 排除最近 12 个不同目标；只要跨类型还有未遇见的内容，就从未遇见池选。
3. 两边都有候选时，再使用现有历史声音概率；仅一边有候选时直接选该边。
4. 全池都进入近期集合时开启新一轮，优先避免立即重复上一段；全池只有一段时允许重复并提示。
5. 首次有普通展品时优先遇见普通人的声音；尚未遇见历史声音时，在第 3 次成功打捞优先安排一次历史声音。历史池为空时不承诺保底，普通池为空时直接提供历史声音。
6. 本人作品不作为日常打捞首选；没有其他可听内容时明确说明，并允许试听本人作品。

当前 guaranteeActive 条件在历史池存在时会让新用户第一次必出历史声音，虽满足“前三次出现”的字面条件，但缺少随机惊喜。改成第 3 次兜底属于体验选择，不应把现状描述成概率故障。

打捞记录表示“遇见”，不表示“听完”。请求失败或没有可用内容不累计成功次数。

**验收：** 用小型普通/历史混合池验证：还有新候选时不重复；前三次兜底按新规则执行；内容耗尽仍可继续；同类型 ID 与异类型同 ID 不相互排除。

### 3.4 编辑不能清掉尚未解决的音频审核结论

**现有问题：** 创建时音频隐私命中会转 REVIEW；编辑只重新审核文字，applyOutcome 在编辑路径中可将该记录设回 PASS。SPEECH 等非演唱内容存在通过编辑跳过原音频复审的路径。

**目标规则：** 最终判定为：有拒绝依据则 REJECT；无拒绝但有未解决的人工复审事项则 REVIEW；全部满足通过条件才 PASS。文字编辑不能代替人工确认音频。

**最小实施：** 保存当前音频是否仍需人工确认及其原因；人工审核处理后关闭该事项，文字修改只重新计算文字结论。保留当前音频不支持替换的约定，不为此建设通用版本系统。

现有音频 ASR 失败只留流水、不一定阻止普通展品公开，是代码明确采用的策略，与语音回音不同。本方案建议：SPEECH 与 SINGING 无法完成音频核验时转人工；ENVIRONMENT 允许按文字规则继续，但界面不能承诺已经完成声音隐私识别。环境声分类仍依赖用户声明，不宣称系统能自动识别所有隐私。

已公开内容修改后，沿用当前单份记录方案：重新审核，进入待审则暂时退出公开馆藏；提交前说明这个影响。待审和驳回时保留编号、音频与回音数据。近期不加入公开旧版与待审新版并存的版本管理。

**验收：** 音频触发 REVIEW 后仅修改标题仍待审；人工通过后合规文字修改按规则重审；文本驳回能修正重投；编号不变化、投稿不重复增加。

## 4. 第二阶段：补齐“听过以后还能找回”

### 4.1 增加真正的收藏

详情页增加“收藏这段声音”，再次点击取消。收藏是个人标记，不改变公开状态，不通知作者，不展示点赞排名。

新增收藏关系：ownerId、targetType、targetId、createdAt，同一账号与目标唯一。支持普通声音和历史之声，沿用现有 TargetType。使用明确的收藏与取消接口，不使用“点击一次反转状态”的请求语义。

“我的声音”保留“我回应过的”，另设“收藏的声音”；两者不能互相代替。目标暂时待审时在收藏中显示“暂不可听”，不返回未公开内容；永久删除时移除收藏关系。不要为每条收藏保存音频副本。

### 4.2 增加最近听过

使用独立试听记录，因为从馆藏点开、首页星星进入、历史专区播放都不会自然产生打捞记录。

建议定义：单次实际播放累计达到 min(10 秒, 总时长的 50%) 后记为“听过”；暂停不累计时间，拖动进度不算已播放。同一用户和目标只更新最近听过时间，个人页显示最近 30 项。此记录用于找回内容，不作为公开热度或奖励依据。

打捞成功、详情页打开、有效试听三个概念分开；近期不建设复杂行为埋点平台。新增 ListenHistory 关系，游客可仅本地保留最近听过，账号保存到后端。

### 4.3 我的声音按任务分区

把现有内容组织成四个入口：

- **我的投稿：** 全部、待复审、已入馆、未通过；每项显示原因与下一步。
- **回音：** 收到的公开回音、我发出的回音；发出列表包含审核状态。
- **收藏与足迹：** 收藏、最近听过，继续区分“我回应过的”。
- **消息：** 审核结果与新回音提醒，显示未读。

“等待复审”不承诺具体处理时间，除非运营方能够兑现。驳回说明指向修改动作，不能只显示状态代码。

### 4.4 回音和消息完成到达闭环

保留公开文字/语音回音，暂不增加楼中楼和私信。

补充“撤回我发出的回音”：由发送人操作；删除公开展示并清理对应语音文件，保留审核流水。若消息已发送，目标不可用时显示明确提示，不继续指向失效的回音。

现有回音消息主要关联展品，点击后无法定位具体一条。为新回音通知增加 echoId，打开详情后定位该回音；审核驳回通知转到本人发出列表或投稿编辑入口，不强行跳到公开不可访问的详情。消息读取失败时保留未读，不先在界面假装成功。

继续保持状态变更、审核流水、消息生成在同一事务里。公开回音才通知展品作者；本人回应本人作品不产生“别人回应了你”的通知，这条现有规则保留。

## 5. 第三阶段：增强馆藏发现与历史策展

### 5.1 从关键词检索扩展到轻量筛选

馆藏新增声音类型、录制时间范围、地点关键词筛选，提供最近入馆/最早入馆排序。地点沿用用户填写的文本，不要求定位权限。

列表先采用普通数据库分页，前端明确展示加载状态。当前数据规模不需要搜索引擎、向量数据库或个性化模型。首页声音星星继续展示真实公开展品，动画只负责视觉，不影响打捞概率。

### 5.2 历史之声形成策展入口

历史声音已有来源、授权、年代等字段，首先用好这些已有信息，区分真实来源音频、演示声音与重建内容。

后续仅在需要管理多期内容时增加简单主题展：标题、介绍、封面、排序后的声音清单、公开状态。先做一到两个真实策展主题，不预建复杂栏目系统。历史声音同样支持收藏和听过记录；本阶段仍不加入历史声音回音体系，避免将只支持普通展品的回音模型强行混用。

### 5.3 审核台支持实际处理工作

利用已有记录增加：按展品/回音筛选、按待审时间排序、同时展示文字与音频原因、查看该对象审核历史。人工拒绝必须写原因；通过理由允许简短说明。近期保留现有管理员入口，不扩建多级角色与权限平台。

## 6. 状态与数据约定

继续使用现有 PENDING / REVIEW / PASS / REJECT，不为用户端再造第二套审核状态。

| 状态/动作 | 公开列表与打捞 | 作者侧 | 允许的后续动作 |
| --- | --- | --- | --- |
| PENDING | 不进入 | 显示处理中 | 等待处理完成，不把它标成已入馆 |
| REVIEW | 不进入 | 待复审及原因 | 编辑重投、删除，或等待人工处理 |
| PASS | 进入 | 已入馆 | 编辑后重新判定、删除 |
| REJECT | 不进入 | 未通过及原因 | 修改重投、删除 |
| 删除 | 目标不再可用 | 从投稿列表移除 | 清理回音与音频、使关联目标失效，保留审核流水 |

新增数据以三类为限：收藏关系、最近试听关系、音频待复审事项字段；通知补充具体回音定位字段。主题展关系放到第三阶段再决定。

暂时待审不删除收藏与回音；永久删除才清理关联。个人入口可以显示“暂不可听”，公共接口仍不返回待审正文或播放地址。作者与审核员访问自己的处理页面走各自入口。

已有账号与内容直接保留；不把游客旧内容批量改归其他账号，不重编馆藏号，不重建数据库。必要的表字段变更按项目已有方式处理，不为本次业务升级引入通用迁移平台。

## 7. 实施顺序与验证交付

### 第一批：身份与判定正确

完成退出/过期游客恢复、登录后返回原操作、前后端操作边界、跨类型打捞去重与第三次兜底、编辑保留音频待审事项。同步修正验收文档中“没有账号、不能跨设备恢复”的过时描述。

这些变更分别验证会话恢复、草稿恢复、内容归属、抽取结果和审核状态。如果出现身份混用、草稿丢失或未审内容公开，修正对应流程后再交付，不以页面看起来成功替代业务结果。

### 第二批：个人使用闭环

完成收藏、最近听过、个人页分区、回音撤回、通知定位。验证取消收藏结果稳定、直接点播也能进入历史、待审收藏不泄露内容、撤回后消息不误导、不同账号列表互不混用。

### 第三批：发现与运营

完成馆藏筛选分页、历史主题试点、审核台筛选。验证筛选组合与分页不漏不重、非公开内容不进入结果、策展内容来源说明可见。

每批都交付对应前后端改动、受影响接口说明与一段可连续演示的流程。复用项目现有测试，新增测试集中在身份切换、打捞规则和审核状态这类确实容易回归的逻辑；不为纯展示调整制造重复测试。

工作量按批次拆任务后再估计，不在尚未确认新规则和交互前承诺固定工期。

## 8. 怎么判断升级有用

先看三条实际体验：注册后能够完成投稿且退出正常；听过的声音能找回来；作者收到回音后能够直接到达那条内容。

如果需要统计，用已有或本次确有用途的数据回答：提交后有多少最终公开、待审积压多久、多少有效试听产生收藏或公开回音。没有有效试听记录前不计算“试听转化率”，打捞次数不能当作收听次数。当前不建立综合评分或无后续用途的数据采集。

## 9. 实施前应确认的两项产品取舍

建议默认采用本文规则，但它们仍是新提案：

1. 游客可听可打捞，正式投稿、回音与收藏需要登录。旧版本游客内容通过注册继承。
2. 已公开作品修改后沿用“单份记录重新审核”，暂不支持旧版继续公开。

其余实现可以围绕这两项展开。本文不授权直接改变现有业务；下一步可先实施第一批，完成后再做收藏与足迹。

## 10. 主要代码依据

以下路径相对于 codes/code；描述的是阅读时的实现。

- frontend/src/api/index.js、store/museum.js：游客会话、账号认证、退出和过期事件。
- frontend/src/router.js、views/LoginView.vue、views/MineView.vue：路由、登录后固定进入 /mine、个人页与通知入口。
- backend/.../service/AccountService.java、SessionService.java 与 web/SessionController.java：游客原行升级注册、按 deviceKey 取回身份。
- backend/.../config/AccountIdentityFilter.java：已登录身份覆盖请求头；未登录携带账号 ID 返回 401。
- backend/.../service/DrawService.java：先选类型、再在类型内排除近期记录，首次历史声音条件。
